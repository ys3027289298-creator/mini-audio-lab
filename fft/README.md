# fft

`make test` 跑自检（迭代基-2 复 FFT、幅度、Parseval、往返一致性）。

## 分块流式频谱（blockfft）

`src/blockfft.c` 是 Hann 窗 + 50% 重叠的 Welch 分块频谱分析器，与整段 FFT
参考共用同一 FFT 核、窗函数和 density 归一化（`P=|Xw|²/(fs·Σw²)`，功率守恒，
与 `scipy.signal.welch` 同约定；相关系数 1.0000）。

- `make bench`：扫描块长 64…2048，输出误差/延迟/耗时 CSV。
- `make bench BLOCKING=0`：**关闭分块**，编译期切回整段 FFT 路径——所有标称块长
  都只缓冲整段再做一次全长度 FFT（即分块功能引入前的逐样本缓冲行为），输出中
  分块行 `navg=0`、误差为 0。
- 默认 `BLOCKING=1`。两种模式均零编译警告。

### 两条互制约标度律（4096 点测试信号，三音 + 噪声）

- 误差下降律（dB 域）：48 kHz 每十倍块长降 18.1 dB（R²=0.96），96 kHz 降 21.4 dB
  （R²=0.994），对应线性功率 E∝B^(−1.8)～B^(−2.1)。
- 延迟上升律：L=B/fs，严格线性，R²=1.000（48 kHz 0.02083 ms/样本，96 kHz 0.01042）。

### 选型结论（三个候选块长 128 / 512 / 1024）

| 候选 | 48k 延迟 / 误差 | 96k 延迟 / 误差 | 双音(350 Hz)分辨 | 判定 |
|---|---|---|---|---|
| 128 | 2.7 ms / 20.9 dB | 1.3 ms / 27.3 dB | 两档均否 | 误差过大，淘汰 |
| 512 | 10.7 ms / 5.9 dB | 5.3 ms / 15.7 dB | 仅 48k 可分辨 | 48k 的拐点 |
| **1024** | 21.3 ms / 1.6 dB | 10.7 ms / 7.1 dB | **两档均可分辨** | **跨采样率首选** |

**选 B=1024，依据：**
1. 它是在**两档采样率下都能分辨 350 Hz 双音**的最小块长——B=512 在 96 kHz 时
   频率分辨率 df=18.75 Hz、间隔仅约 1.9 个 bin，无法分辨（见 `candidates.csv` 的
   `pair_resolved` 翻转）。
2. 两档误差均 ≤7.1 dB，显著小于 128/512；而继续加到 2048，48k 误差仅再降 0.8 dB、
   延迟却翻倍，已处在权衡曲线饱和段（拐点之后）。
3. 延迟 21.3 ms（48k）/ 10.7 ms（96k）仍在游戏音频常见 20–40 ms 帧预算内，CPU 占比
   ≤0.084%（见 `timing.csv`），实时成本可忽略。

若部署固定为 48 kHz 且延迟优先，则取拐点 **B=512**：它在 48k 即可分辨双音、误差
5.9 dB、延迟 10.7 ms，512→1024 只多换 4.3 dB 却把延迟翻倍。
